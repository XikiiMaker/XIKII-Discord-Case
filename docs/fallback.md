# 备用翻译服务

本项目以 Qwen 为主引擎。备用服务兼容 [LibreTranslate 的 /translate API](https://docs.libretranslate.com/api/operations/translate/)，采用批量文本请求、自动源语言检测和中文/英文目标。无需额外 Node.js SDK。

## 配置

在「翻译设置 → 备用翻译」填写自己的服务完整地址，例如 `https://your-service.example/translate`，再填写该服务的 API Key（不要求 Key 的自建服务可留空）。勾选允许使用备用服务后保存。默认关闭，不预置第三方公共服务地址。

远程服务要求 HTTPS。本机 `localhost`、`127.0.0.1`、`[::1]` 可以使用 HTTP。地址不能含账号、密码、查询参数或片段；请求拒绝重定向。服务必须已安装中英模型，是否要求 Key 由服务管理员决定。

备用 Key 与 Qwen Key 分别使用 Electron safeStorage 加密，仅在主进程解密使用。更改备用服务地址会清除其旧 Key，避免把原服务凭据发给新服务。可以单独删除任一 Key。

## 调用行为

- Qwen 成功时不调用备用引擎；失败后至多尝试一次备用请求。
- 当前消息中的代码、URL、Discord 原始提及和自定义表情标记原样保留；将其间待翻译的文字组成数组，一次请求翻译后恢复原顺序。
- 不发送最近对话，也不发送 Qwen Key。分段翻译可能损失跨特殊标记的语义联系；复杂语境优先使用 Qwen。
- 备用译文不是流式输出。切换时清掉未完成的 Qwen 内容，显示备用引擎状态；预览及接收译文带有来源提示。
- 共享请求合并、队列和并发上限；备用请求超时 15 秒。设置改变或退出时取消活动请求；取消 Qwen 不触发备用调用。
- 备用成功结果缓存 1 分钟，之后重新尝试 Qwen；失败不缓存。更换端点或任一 Key 时旧缓存不会复用。
- 两个引擎均失败时保留原文或草稿，不自动发送原文。

## 验证边界

自动测试验证了以上协议、故障切换、取消、缓存与凭据隔离。Electron 模拟测试验证设置保存、独立加密存储、接收显示与一次自动发送。模拟服务不访问外网。

尚未配置真实 LibreTranslate 模型服务，未声称其实际翻译质量或部署可用性已经验证。真实服务验收需要用户配置一个可用地址，使用人工中英文本测试。
