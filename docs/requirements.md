# WebCord 自动翻译项目需求书（修订版）

本文根据项目发起人提供的修订版整理；P0 为核心交付，P1 为增强功能，P2 为后续优化。具体 API、模型可用性及上游扩展机制须在接入时以实际代码和官方文档核对。

2026-09-11 最新确认：本版仅支持中文与英文互译。用户实测后取消翻译预览及底部工具栏，只保留频道/私信名称旁的自动翻译开关，开启后直接翻译发送。此前“可选自动发送、默认预览”的决定已被本条取代。首次启用提示、私信默认开启、频道默认关闭、上下文默认关闭。缓存和上下文管理由本项目新增。追加：默认保持 Discord 登录会话、设置增加开机启动勾选项、检查并补全新消息提醒。下文保留原始需求背景，冲突处以本条和 [implementation-plan.md](implementation-plan.md) 为准。

## 1. 项目概述

基于 WebCord（Electron + TypeScript）二次开发，集成阿里云通义千问 Qwen，通过发送前翻译和接收后本地显示译文，实现跨语言沟通。参考 xikii 会员系统实时自动翻译模块。

私信默认自动开启翻译；频道支持用户手动开关。单次发送的译文语言由本地目标语言设置决定；让每个接收者自动看到各自语言需要接收者一侧的翻译能力，多目标语言输出属于 P2。

## 2. 翻译引擎

采用 Qwen 大语言模型完成翻译，支持语境、语气、术语和混合语言处理，通过专用 Prompt 调整行为。

| 需求 | 说明 | 优先级 |
| --- | --- | --- |
| Qwen API 接入 | 通过 DashScope SDK 或 REST API 调用 | P0 |
| API Key 配置 | 设置面板输入，Electron safeStorage 加密存储 | P0 |
| 模型选择 | 支持 qwen-turbo、qwen-plus、qwen-max 等；接入时核对可用性 | P1 |
| Prompt 模板 | 翻译专用 System Prompt，优先核对并复用 xikii 实现 | P0 |
| 上下文管理 | 最近 N 条对话，按私信或频道隔离 | P1 |
| 流式响应 | 逐步显示译文，减少等待感 | P2 |
| 缓存 | 相同请求避免重复调用，控制成本 | P0 |
| 降级 | Qwen 失败可切换备用翻译引擎 | P2 |

### Prompt 基础模板

```text
你是一个专业的实时翻译引擎。请将用户输入的消息翻译成目标语言。

规则：
1. 保持原文的语气和风格（正式/随意/幽默等）。
2. 保留 Markdown 格式、表情符号、@提及、链接等特殊内容。
3. 对于专业术语，使用行业通用译法。
4. 如果原文已经是目标语言，直接返回原文。
5. 只输出翻译结果，不要添加任何解释。

目标语言：{target_language}
```

上下文增强模板：

```text
以下是最近的对话上下文，供你理解语境：
{context_messages}

请翻译以下消息：
{message_to_translate}
```

消息及历史对话作为待翻译数据处理，不能覆盖系统翻译规则。实施时确认术语、格式保护与上下文边界。

### 语言检测

- P0：自动识别消息语言；已经是中文的接收消息跳过翻译。
- P1：中英混合消息按主要语言处理。
- 可使用 Qwen 同次完成检测与翻译，或使用轻量检测；若要求中文消息完全不产生 API 调用，则需要先行本地判断。待核对 xikii 逻辑后确定。

## 3. 功能需求

### 3.1 接收方向

| 需求 | 说明 | 优先级 |
| --- | --- | --- |
| 自动检测 | 识别收到消息的源语言 | P0 |
| 中文跳过 | 已是中文的消息不触发翻译 | P0 |
| 实时翻译 | 异步调用 Qwen，译文显示在原文下方 | P0 |
| 原文保留配置 | 可选择是否显示原文 | P1 |
| 加载状态 | 翻译中显示指示器 | P2 |
| 上下文感知 | 使用最近对话辅助理解 | P1 |

### 3.2 发送方向

| 需求 | 说明 | 优先级 |
| --- | --- | --- |
| 发送前翻译 | 中文输入翻译后发送 | P0 |
| 默认目标语言 | 用户可配置默认发送语言 | P0 |
| 翻译预览 | 发送前查看译文 | P1 |
| 发送原文 | 快捷键跳过翻译 | P1 |
| 多目标语言 | 可选同时翻译为多种语言，参考 xikii | P2 |

### 3.3 私信

- P0：所有私信默认启用翻译。
- P1：支持全局关闭私信翻译。
- P2：支持单个私信独立关闭。

### 3.4 频道

- P0：每个频道独立开关，新频道默认关闭。
- P1：快捷键或右键菜单快速切换；每频道可配置目标语言。
- P2：开启翻译的频道显示图标。

## 4. 技术方案

WebCord 页面通过 preload 和 IPC 向 Electron 主进程请求翻译，Node.js 翻译服务负责 Qwen 调用、调度、缓存和 Prompt。初始方案可将中间层放在主进程内；如 xikii 架构要求独立 Node.js 服务，再明确部署与鉴权。

| 技术点 | 方案 |
| --- | --- |
| 消息监听 | 评估 MutationObserver 监听 DOM 或 preload 接入消息事件；需求原案提到 WebSocket 拦截，具体采用方式待上游适配验证 |
| Qwen 调用 | DashScope SDK 或 REST；原案端点为 /api/v1/services/aigc/text-generation/generation，SDK 包及协议需核对 |
| 翻译调度 | 主进程队列、并发限制、超时和限流处理 |
| 缓存 | LRU；原案以原文和目标语言为基础，启用上下文或更换模型/Prompt 时应纳入对应影响因素 |
| 设置 | 复用 WebCord 设置机制，密钥使用 safeStorage，禁止明文回退 |
| UI | preload 注入翻译 UI，配合自定义 CSS；需验证上游实际支持 |
| 上下文 | 按私信/频道维护最近 N 条消息环形缓冲，限制条数及文本长度 |
| IPC | 最小化接口，校验调用来源与请求参数，不向远程页面暴露密钥和通用 Node.js 能力 |

## 6. 风险与验证事项

| 风险 | 应对 |
| --- | --- |
| 平台条款与兼容性 | 开发前核对 Discord 与 WebCord 的当前约束，限制测试范围；降低频率不能消除条款风险 |
| Token 成本 | 缓存、上下文限额及合理选择模型 |
| 延迟 | 异步处理，后续支持加载指示与流式响应 |
| 限流 | 队列、并发控制、受限重试 |
| 消息格式 | Prompt 约束并验证 Markdown、表情、提及、链接等内容的保真 |
| 上下文长度 | 限制消息条数与长度，避免跨会话混入 |
| 密钥安全 | safeStorage、本地主进程调用、日志脱敏、禁止提交密钥 |

发送失败应保留草稿并显示错误，不静默发送原文或重复发送。接收翻译失败应保留原消息。以上作为核心流程验收补充。
